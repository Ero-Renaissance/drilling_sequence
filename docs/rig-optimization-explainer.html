Drilling Sequence Planner · Technical Brief

Rig fleet optimization, from first principles

How the planner computes the minimum rig fleet that still meets every yearly drilling commitment — the scheduling model, the year-decomposition that turns it into bin-packing, and the two engines (a greedy heuristic and an exact CP-SAT solver) behind the answer.

The problem

Minimize rigs subject to hard annual delivery

Given a multi-year demand of wells per project per year, find the smallest number of drilling rigs — per terrain — such that every year's committed well count is drilled within that year, under the rig-movement rules.

Rigs never cross terrains, so Land, Swamp, and Offshore are three fully independent optimizations solved side by side. Within a terrain, the objective is min |fleet|; the constraints are a well's rig time, the sequence-dependent movement gaps, and the per-year deadlines. Multiple rigs may work the same project concurrently.

Setup times

Sequence-dependent gaps → a deterministic block length

A rig chains wells; the gap between two consecutive wells depends on where they sit in the chain. Crucially, that structure makes the time to drill m consecutive wells of one project a deterministic function of the count — the lever that later collapses a job-shop-flavored problem into bin-packing.

# rig-days for m consecutive wells of one project block(m) = m·d + Σ(k=1..m-1) g(k) g(k) = G_batch if k mod B == 0 # 4-week batch boundary = G_well otherwise # 2-week inter-well move defaults: d = 76d (2.5 mo) · B = 3 · G_well = 14d · G_batch = 28d

Moving a rig to a different project costs a terrain-specific M (Land 45 d, Swamp/Offshore 30 d). Every parameter is user-editable — a saved parameter set is a scenario.

The structural insight

Under strict in-year delivery, the horizon decomposes by year

A well committed to year Y can't start before 1 Jan Y (no drill-ahead) and must finish by 31 Dec Y (finished-in-year). So no rig-time usefully crosses a year boundary — each year is independent, and a rig bought for a busy year is free again the next. Two consequences:

Per (terrain, year): a 1-D bin-packing. items = project runs with deterministic, grouped costs bin cap = C = days_in_year − maintenance pack to minimize the number of rigs (bins) Per terrain: N = max(over years y) rigs_needed(y) # the fleet is set by the single peak year; rigs reuse across years

This is exact for the strict policy: because the years don't interact, optimizing each independently and taking the max is optimal for the whole horizon. It also means the binding constraint is always a specific peak (project, year), which the tool reports.

The exact engine

The per-year packing as a CP-SAT model

For each (terrain, year) the solver minimizes bins over an integer assignment of wells to rigs. Project wells may split across rigs; the block cost of each split is a table lookup (AddElement), keeping the model linear.

# decision variables a[p][r] ∈ {0 .. c_p} # wells of project p on rig r present[p][r] ∈ {0,1} # a[p][r] > 0 used[r] ∈ {0,1} # rig r carries any work # constraints (per year) Σ_r a[p][r] = c_p ∀p (all wells placed) block[p][r] = AddElement(a[p][r], BLOCK_p) # BLOCK_p = [block(0..c_p)] L[r] = Σ_p block[p][r] + M·(distinct[r] − used[r]) L[r] ≤ C ∀r (rig load ≤ year) used[r] ≥ used[r+1] # symmetry breaking # objective minimize Σ_r used[r]

distinct[r] = Σ_p present[p][r] is the number of projects on the rig, so M·(distinct − used) charges one inter-project move per project after the first. Solved single-threaded for determinism, with a 10 s guard the tiny instances never approach.

The formal integer program

Stated as a pure MILP for one (terrain, year). The nonlinear block cost is linearized with a one-hot count selector zp,r,m — exactly the table the CP-SAT AddElement encodes.

Sets & parameters
P projects, cp wells of p this year  ·  R = {1..Σp cp} rigs
blockm = rig-days for m consecutive wells (constant)  ·  M move  ·  C year capacity
Decision variables
zp,r,m ∈ {0,1}rig r does exactly m wells of project p
yp,r ∈ {0,1}project p present on rig r
ur ∈ {0,1}rig r used
Objective
minimize   Σr ur
Subject to
Σm zp,r,m = 1∀ p, r  (one count per project·rig)
Σr Σm m·zp,r,m = cp∀ p  (place every well)
yp,r = Σm≥1 zp,r,m∀ p, r  (presence)
ΣpΣm blockm·zp,r,m + M(Σp yp,r − ur) ≤ C∀ r  (rig load ≤ year)
yp,r ≤ ur ≤ Σp yp,r∀ p, r  (rig is “used” iff it carries work)
ur ≥ ur+1∀ r  (symmetry breaking)
Fleet
Nterrain = maxy ( Σr ur solved for year y )
Years are independent under the strict in-year policy, so the terrain fleet is the peak year's bin count — each year is solved as its own instance of the program above.
Two engines

Greedy by default, exact on demand

Default · owned code

Heuristic

  • Longest-project-first (LPT) ordering; each well assigned to the rig giving the earliest feasible start (≡ earliest finish under uniform duration).
  • Outer loop grows the fleet until all deadlines are met.
  • Roughly O(F·W·R); no dependencies.
  • Greedy bin-packing is not optimal — it can over-assign by a rig on adversarial packings.
Optional · OR-Tools

Exact — CP-SAT

  • Per-(terrain, year) bin-packing solved to proven optimality.
  • Returns the true minimum fleet; never exceeds the heuristic.
  • Instances are tiny (P ≲ 15, wells/yr ≲ 30) → millisecond solves.
  • Selected via OPTIMIZER_ENGINE=milp; degrades to the heuristic if the solver isn't installed.

Concrete gap. On a mixed Swamp demand in our test suite the greedy heuristic returns 6 rigs where CP-SAT proves 5 suffice — one rig of capital saved, with a certificate of optimality. The invariant exact ≤ heuristic (both feasible) is asserted in tests.

Scope & honesty

Where the exact engine steps aside

The year-decomposition is valid only under the strict in-year policy. The relaxation toggles that couple adjacent years break that independence, so the exact engine declines and the request runs on the heuristic — with a warning in the response, never a silent substitution.

ToggleEffect on the model
spudded deliveryA well may finish in the next year → the year's load is no longer self-contained.
drill-aheadA well may start before its committed year → cross-year scheduling.
slip past year-endDeadline extends beyond 31 Dec → adjacent years share capacity.
Outputs

What you get back

Minimum rigs per terrain and the per-year fleet profile; the binding (project, year) that sets each fleet; a rig-by-rig Gantt (the same visual language as the campaign sequence, rigs named Land Rig 1 … Offshore Rig n); per-rig utilization; and an Excel workbook (summary, full rig schedule, and the demand table). Infeasible terrains are called out explicitly.
